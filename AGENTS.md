# Agentic Transaction Categorizer

LLM pipeline that ingests monthly transaction CSVs from multiple banks (Chase, Apple, Venmo, Sam's Club, Ally) and assigns each transaction to one of ~25 spending categories. The agent loop ranks past categorizations by Levenshtein similarity and consults iMessage / Google Calendar / Gmail / Perplexity to disambiguate edge cases.

## Layout

Code lives in the `categorizer/` package; the two root scripts
(`categorize_transactions.py`, `agent_eval.py`) are thin wrappers over
`categorizer.pipeline.main` / `categorizer.eval.main`. Paths are resolved
through `categorizer/paths.py` (`PROJECT_ROOT`, `CONFIG_DIR`, `OUTPUT_DIR`,
`DATA_DIR`). Hand-edited/secret inputs live in `config/`, generated artifacts in
`output/`, monthly bank CSVs in `data/`. `categorizer/__init__.py` calls
`load_dotenv(config/.env)` on import, so env vars are populated before any
submodule reads `os.environ`. Subpackages: `categorizer/archive/`
(`sheets.py`, `index.py`, `google_auth.py`) and `categorizer/tools/`
(`messages.py`, `calendar.py`, `gmail.py`, `web.py`, with `__init__.py` holding the
`@tool`-decorated wrappers plus `AGENT_TOOLS` / `TOOL_NAMES`);
`categorizer/categories.py` is the category loader.

## Run

- End-to-end: `.venv/bin/python categorize_transactions.py` — prompts for a `YYYY-MM` period, reads `data/<yyyy>-<mm>/*.csv`, writes `output/categorized_transactions.csv`, then **writes a new month tab into the current-year archive sheet** (see Non-obvious). Not a dry run — it mutates the live spreadsheet on every invocation.
- Held-out eval: `.venv/bin/python agent_eval.py [--k 4] [--year 2026] [--frac 0.25] [--seed 42] [--concurrency 5] [--csv [PATH]]` (impl in `categorizer/eval.py`) — deterministically holds out a fraction of the first k months' archived transactions, hides those rows from the example pool, then **always** syncs them to a LangSmith **dataset** and runs the agent as an **experiment** via `aevaluate`, scored by an exact-match `correct` evaluator. Results (per-example traces + auto token/cost/latency) land in LangSmith's Datasets & Experiments tab. Needs `LANGSMITH_API_KEY`; reuses an existing dataset (name encodes year/k/frac/seed) as-is rather than refreshing it. `--csv` **optionally** also writes the old local report to `output/agent_eval_report.csv` (bare `--csv`) or a given path (token counts, USD cost, runtime, accuracy, per-tool invocation rate, per-category sensitivity/precision, per-transaction breakdown); predictions are joined back to ground truth by a deterministic `example_id`. Makes live API + tool calls. CSV costs come from `categorizer.agent.MODEL_PRICING` — add an entry there when changing `agent.MODEL`, or `compute_cost` raises.
- Smoke-test the archive fetch alone: `.venv/bin/python -m categorizer.archive.sheets`.
- Retry a failed sheet write without re-paying for the LLM calls: `.venv/bin/python -m categorizer.archive.sheets --push [CSV] [--month N]` — pushes an already-categorized CSV (default `output/categorized_transactions.csv`) to a new month tab. Month is inferred from the CSV's dates; a CSV spanning multiple months errors instead of guessing.
- No automated tests. Exercise changes through one of the entry points above.

## Required setup (per machine, all gitignored; live in `config/`)

- `config/.env` — `OPENAI_API_KEY` and/or `FIREWORKS_API_KEY` (only the one matching `categorizer.agent.PROVIDER` is needed), `PERPLEXITY_API_KEY`, `VENMO_ACCOUNT_HOLDER_NAME`, `CURRENT_YEAR_ARCHIVE_SHEET_ID`, `PAST_YEAR_ARCHIVE_SHEET_ID`, and (optional) `LANGSMITH_TRACING` / `LANGSMITH_API_KEY` / `LANGSMITH_PROJECT` for LangSmith tracing. Template: `config/.env.sample`.
- `config/categories.yaml` — authoritative category list plus optional per-category `instructions`. Template: `config/categories.sample.yaml`.
- `config/credentials.json` + `config/token.json` — Google OAuth (read-only Calendar + Gmail, **read/write Sheets**). All three APIs must be enabled in the same Cloud project as the OAuth client.
- Monthly bank CSVs in `data/<yyyy>-<mm>/` following the filename-prefix convention in `config/transaction_csv_sources.md`.
- **Full Disk Access** for the launching app (Terminal/iTerm/VS Code). The `search_messages` tool reads `~/Library/Messages/chat.db` (`IMESSAGE_DB_PATH` in `categorizer/tools/messages.py`); without FDA on the app that starts the process, that read fails. Grant it to the app bundle, not to `python`, then relaunch.
- **`langsmith` MCP server (for coding-agent access to LangSmith, not used by the pipeline).** Defined in `.mcp.json` as a stdio server running `uvx langsmith-mcp-server`, with `LANGSMITH_API_KEY` passed via `${LANGSMITH_API_KEY}` expansion. The coding-agent host receives this value from its **launch environment**, not from the pipeline's `config/.env` loading, so export it in the shell before starting the agent — e.g. `export $(grep -v '^#' config/.env | xargs)` — or add the key to your shell profile. If it is unset, LangSmith calls return 401. Requires an MCP-capable coding-agent host and `uvx` (from `uv`) on `PATH`.

## Non-obvious

- **LangChain `create_agent`, on OpenAI or Fireworks.** `categorizer/agent.py` builds one chat model via `_build_model()` (selected by the `PROVIDER` constant, `"openai" | "fireworks"`) and a `create_agent(...)` harness at import, reused across all transactions. OpenAI uses `ChatOpenAI(use_responses_api=True, reasoning_effort=...)` with explicit `prompt_cache_key`/`prompt_cache_retention`; Fireworks uses `ChatFireworks` (Chat Completions) with fully-qualified model ids (`accounts/fireworks/models/<slug>`), `FIREWORKS_API_KEY`, automatic prompt caching (no cache-key param — `PROMPT_CACHE_KEY` rides along in the `user` session-affinity field), and `REASONING_EFFORT` set to `None` for models that reject that field. On Fireworks, `reasoning_tokens` reports 0 (langchain-fireworks doesn't map them; `output_tokens` still includes them, so cost is unaffected) and `cached_input_tokens` is 0 unless the API returns `prompt_tokens_details.cached_tokens`, which makes reported cost an overestimate. Add a `MODEL_PRICING` entry (Standard serverless tier) for any new model, and note that eval experiment names use only the last path segment of the model id. `categorize_one` calls `agent.ainvoke(...)`; the final category comes back as structured output (`result["structured_response"]`, a `Categorization` Pydantic model built from `CATEGORIES`), not a terminal tool call. Token usage and per-tool counts are summed from `result["messages"]` (`AIMessage.usage_metadata`, `.tool_calls`) by `_aggregate_run`. The non-terminal tools (`search_messages` / `search_calendar` / `search_gmail` / `web_search`) are `@tool`-decorated in `categorizer/tools/__init__.py` (`AGENT_TOOLS`, `TOOL_NAMES`) and each degrades a failure to a JSON `{"error": ...}` string. Tracing to LangSmith activates automatically when the `LANGSMITH_*` env vars are set; absent the key it no-ops. On hitting the recursion limit (mapped from `MAX_ROUNDS`) the run errors out rather than forcing a guess. Verify LangChain + Responses API docs before changing the model surface.
- **`config/categories.yaml` is the authoritative category list (gitignored; template `config/categories.sample.yaml`).** `categorizer.categories._load_categories()` reads it at import into `CATEGORIES` (tuple of names) and `CATEGORY_INSTRUCTIONS` (`{name: optional per-category guidance}`); the loader raises on a missing/malformed file or duplicate names rather than degrading. Each entry's `instructions` (optional, defaults to `""`) is appended to that category's bullet in the agent prompt. Archive rows whose category isn't in `CATEGORIES` are silently dropped from the similarity pool — intentional, see comment at `categorizer.pipeline.load_archive`. This also retires prior-year categories that no longer exist. Renaming a `name` orphans existing archive rows, so the `acessories` typo is kept deliberately.
- **Two archive sheets, combined.** `load_archive()` concatenates `CURRENT_YEAR_ARCHIVE_SHEET_ID` and `PAST_YEAR_ARCHIVE_SHEET_ID`; both are required (the prior-year sheet supplies the trailing-year history early-year transactions need).
- **Trailing 12-month example window.** `categorizer.agent.categorize_one` restricts each transaction's example pool to the 12 calendar months strictly before its own month (`ARCHIVE_WINDOW_MONTHS`), so the agent never sees same-month/future history. Applies to both production and eval.
- **Archive `Date` is a Sheets serial number.** `categorizer/archive/sheets.py` reads `A33:E` and converts column A from a days-since-1899-12-30 serial (because of `UNFORMATTED_VALUE`) to a datetime; unparseable dates become `NaT`. The writer must therefore use `valueInputOption="USER_ENTERED"` so its `YYYY-MM-DD` strings become real date cells — RAW would store text that reads back as `NaT`.
- **The pipeline writes its results back as a new month tab.** `sheets.write_month_tab(frame, month)` runs unconditionally at the end of `pipeline.main`, after the CSV and the `open` calls, so a Sheets failure raises without costing the run's work. It `duplicateSheet`s the latest month tab *before* the target month (preserving the rows 1-32 summary block and formatting), derives the new name by swapping the month word (`July 2026` → `August 2026`), clears `A33:F`, and writes Date/Name/Amount/Category/Account/**Reasoning** at A33. Column F is inert — the reader only takes `A33:E`. It raises rather than overwriting if a tab for that month already exists. Rows whose agent call failed land in the live sheet with a literal `"ERROR: ..."` category. For a target month earlier than every existing tab (January in a fresh year sheet), it falls back to duplicating the *latest* tab instead of erroring.
- **No CSV fallback for the archive.** If a sheet ID is wrong or Sheets is unreachable, `load_archive()` raises rather than degrading to a stale local file.
- **OAuth re-auth is automatic in two cases.** `categorizer.archive.google_auth.load_credentials()` forces a fresh browser flow (1) when `config/token.json` was issued for a narrower scope set than `SCOPES` (instead of 403-ing on the new API later) — the comparison **must** read the `scopes` field out of `token.json` itself, via `_stored_scopes()`, because `from_authorized_user_file(path, SCOPES)` makes `creds.scopes` echo back the requested scopes rather than the stored ones (google-auth only falls back to the stored value when `scopes is None`), which silently defeated this check for every scope change until Aug 2026; an unreadable/corrupt token file is likewise treated as "re-authenticate" — and (2) when refreshing a stored token raises `RefreshError`/`invalid_grant` (revoked or expired refresh token — OAuth clients in "Testing" status expire refresh tokens after 7 days); the dead `token.json` is deleted and the flow restarts. Caveat: this hangs in headless/scheduled runs since `run_local_server` waits for a browser.
- **Sheets API truncates trailing empty cells.** `categorizer/archive/sheets.py` pads short rows to 5 columns; rows missing `Name` or `Category` are silently skipped as incomplete entries.
